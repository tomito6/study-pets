# App de computador (Windows) — a casca (Electron)

2026-11-25, na mesma tarde do app de iPhone. Pedido do Tomi: "eu gostaria também um app de
Windows. Então um app de Windows, Apple e site."

## A decisão

**Electron**, numa pasta própria (`desktop/`), abrindo o MESMO build que o iPhone usa
(`dist-native`, sem service worker). Uma base de código, três cascas: site (Vercel), iPhone
(Capacitor) e computador (Electron).

Descartados:

- **Só o PWA instalado** ("Instalar este site como aplicativo" no Edge/Chrome) — já funciona
  hoje e dá uma janela própria de graça. Mas é uma janela do Edge: o relógio continua sendo
  estrangulado em segundo plano, que é a dor que a extensão do navegador foi criada pra
  contornar em 2026-09-15. E nesta máquina o Cold Turkey manda no `msedge.exe`.
- **Tauri** — instalador de ~10 MB em vez de ~90, mas roda em cima do WebView2
  (`msedgewebview2.exe`), pede Rust instalado pra compilar, e ninguém sabe o que o Cold Turkey
  faz com o WebView2. O Electron traz o próprio Chromium, com o nome do app
  (`Study Pets.exe`): mesmo motor do navegador em que o app é testado, e nada de Rust.
- **Capacitor + `@capacitor-community/electron`** — a ponte da comunidade está sempre uma ou
  duas versões atrás do Capacitor, e o app não usa plugin nenhum que precise dela.

## O que entrou

- `desktop/` com `package.json` PRÓPRIO: o Electron (~110 MB) só é baixado por quem roda
  `npm run desktop:install`. O `npm install` da raiz e o deploy da Vercel não mudam em nada —
  `tests/desktop-app.test.ts` cobra que nenhuma dependência `electron*` suba pra raiz.
- `desktop/main.cjs` — a janela. O app é servido por um esquema próprio, `app://study-pets/`:
  origem estável (é ela que guarda o login e o cache offline do Firestore no IndexedDB) e
  nenhum servidor local aberto. A página roda isolada (`contextIsolation`, `sandbox`, sem
  Node). `backgroundThrottling: false` — **o motivo de a casca existir**: o `setInterval` do
  timer continua de segundo em segundo com a janela minimizada, então o som e a notificação
  do fim do bloco saem na hora, sem extensão.
- `desktop/app-paths.cjs` — as duas regras puras (qual arquivo responde a um endereço, sem
  sair da pasta do build; o que pode ser entregue ao navegador do sistema), testadas pelo
  Vitest da raiz sem instalar o Electron.
- `desktop/preload.cjs` — expõe `window.studyPetsDesktop = { shell: 'desktop' }`, e só isso.
  `isNativeApp()` passa a responder "sim" também aqui (`isDesktopApp()` distingue as duas
  cascas), então o que o iPhone já fazia vale igual: Firebase Auth por `initializeAuth`, o
  botão do Google trocado pelo aviso, e os documentos legais apontando pro site publicado.
- Link pra fora abre no navegador do sistema (`shell.openExternal`, só http/https/mailto) e a
  janela nunca navega pra fora do app.
- **Fechar no modo hardcore**: o `beforeunload` que `unloadGuard.ts` arma, no Electron, faz a
  janela simplesmente não fechar, calada. A casca escuta `will-prevent-unload` e pergunta
  ("Continuar estudando" / "Sair mesmo assim"). Sair continua custando o combinado: o
  abandono é cobrado na próxima abertura, pelo `resumeHardcoreOnBoot` de sempre.
- Uma janela só (abrir o atalho de novo traz a que existe), sem a barra de menu do Electron
  no app instalado.
- `npm run desktop` (builda e abre), `npm run desktop:dist` (gera o instalador em
  `desktop/release/`), `npm run test:desktop` (abre o app de verdade, em modo teste, e confere
  cinco coisas — `e2e/desktop.spec.ts`).

## Como rodar (no Windows)

```
npm run desktop:install   # uma vez — baixa o Electron
npm run desktop           # builda o app e abre a janela
npm run desktop:dist      # gera desktop/release/Study Pets Setup 0.1.0.exe
```

## O que foi conferido, e onde

Num Linux, com tela virtual (não num Windows):

- A casca abre o build de teste inteiro: onboarding, a corrida de setup, o Plano no layout de
  tela grande. `npm run test:desktop`: 5 de 5.
- O build de VERDADE (com Firebase) abre na tela de login em ~100 ms — o `initializeAuth` não
  trava na origem `app://` — com o aviso no lugar do botão do Google.
- O empacotamento pro Windows (`electron-builder --win`) monta `Study Pets.exe` com o ícone
  do personagem, o `app.asar` com os três arquivos da casca e `resources/web` com o build.
  O ÚLTIMO passo (o instalador NSIS) precisa do Windows (ou do `wine`), e não rodou aqui.

## O que NINGUÉM conferiu ainda

Só o Windows do Tomi prova:

1. **O `.exe` nunca foi executado.** Tudo acima rodou com o Electron de Linux.
2. **Cold Turkey Blocker.** O executável é `electron.exe` (no `npm run desktop`) ou
   `Study Pets.exe` (instalado), não `chrome.exe`/`msedge.exe`, que são os nomes que ele
   procura. Deve passar; se não passar, o que ele fecha é a janela do Study Pets, não o
   navegador. Conferir antes de confiar.
3. **Login com e-mail e senha saindo de `app://study-pets`.** Se a chave da API do Firebase
   tiver restrição por referenciador HTTP no console do Google Cloud, o pedido é recusado e a
   origem tem que ser liberada lá. (A mesma dúvida do `capacitor://localhost` do iPhone.)
4. **A notificação do Windows.** No app instalado ela precisa do atalho no Menu Iniciar, que o
   instalador cria; no `npm run desktop` pode sair com o nome "Electron" ou não sair. O som
   não depende disso.
5. **O som com a janela minimizada de verdade** — é o ganho prometido; `getBackgroundThrottling()`
   devolve `false`, mas ouvir é outra coisa.
6. **SmartScreen.** O instalador não é assinado: o Windows mostra "O Windows protegeu o
   computador" e pede "Mais informações → Executar assim mesmo". Pra uso próprio, tudo bem;
   pra distribuir, precisa de certificado (ver abaixo).
7. "Baixar (JSON)" (o Electron abre o "Salvar como" do sistema) e "Restaurar de um arquivo".

## O que NÃO funciona no app de computador, e é sabido

- **Bloqueio de sites.** A extensão conversa com a ABA do app no navegador; a janela do
  Electron ela não enxerga. A seção continua nas Configurações e vai dizer "extensão não
  encontrada" pra sempre. Quem usa o bloqueio continua no site por enquanto.
- **Entrar com Google** — igual ao iPhone: popup não funciona dentro de app, e o Google
  recusa login em janela embutida. Quem criou a conta pelo Google entra no app com e-mail e
  senha depois de definir uma senha pelo "Esqueci a senha" (o Firebase manda o e-mail de
  redefinição também pra conta que só tem Google, e a senha passa a valer junto com ele).
  **Isso não foi conferido com a conta do Tomi** — é o primeiro teste a fazer.
- O login do app de computador é separado do login do navegador (são origens diferentes). Os
  dados são os mesmos: vêm da conta.

## Próximos passos, em ordem

1. O Tomi roda `npm run desktop` e a lista acima.
2. **Entrar com Google no computador**: abrir o navegador do sistema, voltar pro app por um
   endereço próprio (`studypets://`) ou por uma porta local, e trocar o código por credencial
   (`signInWithCredential`). É o mesmo trabalho do iPhone por outra porta; vale fazer os dois
   juntos.
3. **Bloqueio de sites sem o navegador**: ou a extensão passa a falar com o app por
   *native messaging*, ou o app de computador ganha um bloqueio próprio. Decisão do Tomi —
   e ele já tem o Cold Turkey.
4. Ícone na bandeja ("fechar a janela não para o timer") e iniciar com o Windows — só se
   fizerem falta.
5. Distribuir pra outras pessoas: certificado de assinatura (sem ele, SmartScreen), atualização
   automática (`electron-updater`) e, se for o caso, a Microsoft Store.
